# README.md 撰寫規範

> 本規範規定 `README.md` **該寫什麼、怎麼寫**，不規定專案的技術選型。
> 通用規範，任何專案皆適用。

---

## 1. 目的與適用範圍

### 1.1 目的

讓任何人在**三十秒內**判斷「這個東西是不是我要的」，並在**五分鐘內**真的用起來。

### 1.2 讀者

README 的讀者是**使用者**——也就是**這個產物的消費者**：

| 專案型態 | 使用者是誰 |
| :--- | :--- |
| 桌面 / 行動應用程式 | 操作它的人 |
| 函式庫 (library) | 在自己專案裡引用它的開發者 |
| 命令列工具 (CLI) | 在終端機執行它的人 |
| 服務 / API | 呼叫它的人 |

### 1.3 邊界

用**「用它」還是「改它」**切，不用「技術/非技術」切：

- **用它** → `README.md`
- **改它** → `DEVELOPER.md`

因此環境建置、建置指令、測試、目錄結構、架構說明**一律不進 README**（見 §6）。

### 1.4 本規範不管什麼

- 不管專案用什麼語言、框架、建置工具
- 不管 README 的視覺風格（emoji、徽章、排版偏好由專案自訂）
- 不管 `DEVELOPER.md`、`CHANGELOG.md` 的內容（各見其規範）

### 1.5 強制語彙

| 用詞 | 意義 |
| :--- | :--- |
| **必須** | 不做就是不合規（MUST） |
| **建議** | 有更好的理由才可以不做（SHOULD） |
| **可** | 自行斟酌（MAY） |

## 2. 檔案位置與命名

- 檔名**必須**為 `README.md`，**必須**放在儲存庫**根目錄**。
- 編碼**必須**為 **UTF-8 無 BOM**，換行**必須**為 **LF**，檔尾**必須**留一個換行。
- 語言**必須**為**繁體中文**；指令、檔名、API 名稱、專有名詞保留原文，首次出現時加中譯。

### 2.1 內容外拆

單一章節過長時，**可**把細節拆到 `docs/` 底下（例如 `docs/使用說明.md`），但：

- §3 的每個必要章節**必須**在 README 保留**標題與至少一段摘要**，再連結過去。
- **禁止**把 README 縮成只有連結的目錄頁。

---

## 3. 結構：必要章節 / 選用章節

### 3.1 必要章節（依此順序）

| # | 章節 | 必須回答的問題 |
| :-: | :--- | :--- |
| 1 | 專案名稱 + 一句話定位 | 這是什麼？給誰用？ |
| 2 | 這是什麼 / 能做什麼 | 它解決什麼問題？有哪些主要功能？ |
| 3 | 取得與安裝 | 去哪下載？需要什麼環境？怎麼裝？ |
| 4 | 快速開始 | 從裝好到看見結果，最短路徑是什麼？ |
| 5 | 常見問題 / 疑難排解 | 卡住了怎麼辦？ |
| 6 | 授權 | 我能拿它做什麼？ |
| 7 | 開發者入口 | 我想改它，去哪？（連結 `DEVELOPER.md`） |

順序**不得**調換。沒有內容的必要章節**必須**保留標題並註明現況（例如「目前無已知問題」），**不得**刪除。

### 3.2 選用章節

| 章節 | 建議放置位置 |
| :--- | :--- |
| 截圖 / 操作動畫 | 第 2 節之後 |
| 相容性對照表 | 第 3 節之內 |
| 已知限制 | 第 5 節之前 |
| 致謝與來源參考 | 第 6 節之前 |
| 變更紀錄連結（→ `CHANGELOG.md`） | 第 7 節旁 |

## 4. 撰寫規則

### 4.1 語氣與人稱

- 對使用者用「你」，不用「您」「使用者」「本人」。
- 用祈使句寫步驟：「按下開始」，不是「使用者可以按下開始按鈕」。
- 陳述事實，不推銷。**禁止**「業界領先」「完美支援」這類無法驗證的形容。

### 4.2 標題層級

- 全文**只有一個** H1（`#`），即專案名稱。
- 必要章節用 H2（`##`），其下最多再兩層（H3、H4）。**禁止** H5 以下。

### 4.3 程式碼區塊

- **必須**標註語言（```bash、```powershell、```json…）。
- 指令**必須**一行一條，**禁止**帶提示符（`$`、`>`、`PS>`），使用者才能整段複製。
- 需要說明的指令用行內註解，不要在區塊外另寫一段。

### 4.4 連結與圖片

- 庫內連結**必須**用相對路徑（`docs/使用說明.md`），**禁止**寫成絕對網址或本機路徑。
- 圖片**必須**放在庫內（建議 `docs/images/`），**必須**有替代文字。
- 外部連結**必須**寫清楚指向何處，**禁止**只寫「連結」「這裡」。

### 4.5 表格

規格、相容性、對照關係用表格，不用巢狀項目符號。

### 4.6 長度

必要章節齊全的前提下越短越好。超過 200 行時**建議**依 §2.1 外拆。

## 5. 範例與註解慣例

### 5.1 佔位符

需要使用者替換的部分**必須**用角括號包住，內容為繁中描述：

```text
[<專案名稱>][<版本號>][Setup].exe
```

**禁止**用 `xxx`、`your-app`、`TODO` 之類的佔位方式。

### 5.2 範例的可執行性

- 指令範例**必須**能原樣執行（佔位符除外），**禁止**貼未驗證過的指令。
- 範例中的版本號一律用 `v1.0.0`，路徑一律用相對路徑。
- 需要示範虛構專案時，一律用 `MYAPP`。**禁止**用真實的其他專案名稱。

### 5.3 註解

- 程式碼區塊內用該語言的註解符號，Markdown 內用 `<!-- -->`。
- 註解一律繁中，用來說明**為什麼**，不重複指令本身在做什麼。

## 6. 禁止事項

| 禁止寫進 README | 應該寫在哪 |
| :--- | :--- |
| 開發環境建置、相依套件安裝 | `DEVELOPER.md` |
| 建置、打包、測試指令 | `DEVELOPER.md` |
| 目錄結構、架構說明、設計決策 | `DEVELOPER.md` |
| 分支策略、commit 格式 | `DEVELOPER.md` |
| 逐版變更紀錄 | `CHANGELOG.md` |
| 發佈流程、產物命名 | `RELEASE_RULES.md` |

另**禁止**：

- 本機絕對路徑（`D:\...`、`/home/...`）、個人帳號、金鑰、憑證密碼。
- `TODO`、`待補`、`施工中` —— 沒寫好就不要留標題。
- 尚未發佈的功能。README 描述的**必須**是使用者現在下載得到的版本。
- 與 `CHANGELOG.md` 重複的完整更新清單。

## 7. 檢查清單

發佈前逐項確認：

- [ ] 檔案在根目錄，UTF-8 無 BOM、LF、檔尾一個換行
- [ ] 七個必要章節齊全且順序正確
- [ ] 只有一個 H1
- [ ] 第一段就講清楚「這是什麼、給誰用」
- [ ] 「取得與安裝」寫明下載位置與系統需求
- [ ] 「快速開始」的步驟自己實際跑過一遍
- [ ] 所有指令區塊標了語言、沒有提示符、可原樣複製
- [ ] 所有連結可點、圖片顯示正常、圖片有替代文字
- [ ] 沒有任何建置 / 測試 / 架構內容（§6）
- [ ] 沒有絕對路徑、金鑰、個人資訊
- [ ] 沒有 TODO 與未發佈功能
- [ ] 描述的功能與目前最新發佈版本一致
- [ ] 末尾有指向 `DEVELOPER.md` 的入口
