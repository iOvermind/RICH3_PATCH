# 發佈規範

> 本規範規定**發佈時產出什麼、怎麼命名、怎麼驗證、怎麼公開**。
> 通用規範，任何專案皆適用。

---

## 1. 目的與適用範圍

### 1.1 目的

讓使用者拿到的每一個檔案，都能一眼看出「是哪個專案、哪一版、哪種形式」，並且能自行驗證它沒有被掉包。

### 1.2 適用對象

本規範**規範流程，不規範任何一份文件**。專案**不需要**建立 `RELEASE.md`。

### 1.3 本規範不管什麼

- 不管版本號怎麼訂 → `VERSION_RULES.md`
- 不管變更紀錄怎麼寫 → `CHANGELOG_RULES.md`
- 不管**要出哪些形式的產物**——由各專案在 `DEVELOPER.md` §7「建置與產物」明列（見 §3.1）

### 1.4 強制語彙

| 用詞 | 意義 |
| :--- | :--- |
| **必須** | 不做就是不合規（MUST） |
| **建議** | 有更好的理由才可以不做（SHOULD） |
| **可** | 自行斟酌（MAY） |

## 2. 產物命名與識別

### 2.1 檔名格式

所有對外發佈的產物**必須**依此格式命名：

```text
<專案名稱>-<版本號>-<形式>.<副檔名>
```

| 欄位 | 規則 |
| :--- | :--- |
| `<專案名稱>` | 儲存庫名稱 |
| `<版本號>` | **帶 `v`** 的語意化版本號 |
| `<形式>` | 產物形式標記，取自 §2.2 |

分隔符**必須**是半形連字號 `-`；檔名**只能**包含 `A-Z`、`a-z`、`0-9`、`.`、`-`、`_`。

> **為什麼把字元限制得這麼死**：GitHub Release 上傳附件時，會把不在
> `A-Za-z0-9.-_` 範圍內的字元一律換成點。中括號、空格都會被改掉——
> `[MYAPP][v1.0.0][Setup].exe` 上傳後會變成 `MYAPP.v1.0.0.Setup.exe`。
> 本機與線上檔名一旦不同，`SHA256SUMS.txt` 就對不上，使用者無從驗證。
> 限制在這個字元集內，本機產物與發佈附件才會**逐字相同**。

範例（虛構專案 `MYAPP`）：

```text
MYAPP-v1.0.0-Setup.exe
MYAPP-v1.0.0-Portable.exe
```

### 2.2 形式標記

專案有用到才需要，命名**必須**取自下表，**禁止**自創：

| 標記 | 意義 |
| :--- | :--- |
| `Setup` | 安裝版 |
| `Portable` | 免安裝版 |
| `Source` | 原始碼封存 |

需要新增標記時，**必須**先更新本規範，不得在單一專案臨時發明。

### 2.3 Tag 命名

- git tag **必須**為 `v<版本號>`（`v1.0.0`），**不帶**專案名稱與形式標記。
- tag **必須**建立在實際打包所用的那個 commit 上。

## 3. 結構：發佈流程

### 3.1 產物形式由專案決定

本規範**不強制**任何專案出哪幾種形式的產物。各專案**必須**在 `DEVELOPER.md` §7「建置與產物」明列自己會產出哪些形式、各自的用途。

一旦列出，**每次發佈都必須全數提供**，**禁止**某一版少出一種。

### 3.2 必要步驟（依此順序）

| # | 步驟 | 產出 |
| :-: | :--- | :--- |
| 1 | 確認發佈門檻（§4.1） | — |
| 2 | 更新版本號（依 `VERSION_RULES.md`） | 各設定檔 |
| 3 | 轉換 `CHANGELOG.md` 的 `[Unreleased]` 區塊 | 版本區塊 |
| 4 | 本機打包並檢查產物名稱 | 全部產物 |
| 5 | 簽章（若適用，§4.2） | 已簽章產物 |
| 6 | 產生校驗碼（§4.3） | `SHA256SUMS.txt` |
| 7 | 建立並推送 tag | `v<版本號>` |
| 8 | 建立 GitHub Release 頁面（§4.4） | Release |
| 9 | 處置被取代的舊版本（§4.5） | — |

### 3.3 選用步驟

- 由 CI 自動建置與上傳
- 實機安裝驗證
- 對外公告

## 4. 執行規則

### 4.1 發佈門檻

以下全部成立才可發佈：

- [ ] 所有預計發佈的變更均已合併至主分支
- [ ] 建置成功，基本功能實測通過
- [ ] `CHANGELOG.md` 已完成 `[Unreleased]` 的轉換，且日期為實際發佈日
- [ ] 版本號一致性已依 `VERSION_RULES.md` §7 逐項核對
- [ ] `README.md` 描述的功能與本次發佈內容一致
- [ ] 產物檔名完全符合 §2.1 的格式與字元限制

### 4.2 簽章與 SmartScreen

- 可執行產物**建議**簽章。
- 使用**自簽憑證**時，`README.md` 的「常見問題」節**必須**說明：使用者可能看到 SmartScreen 或防毒警告、為什麼會出現、如何確認檔案來源正確（對照校驗碼）。
- 憑證檔與其密碼**禁止**進入版本控制（見 `DEVELOPER.md` §9）。
- 未簽章時**禁止**在文件中宣稱產物「已簽章」或「安全無虞」。

### 4.3 校驗碼

- 每次發佈**必須**提供所有產物的 **SHA-256** 校驗碼。
- **必須**以單一檔案 `SHA256SUMS.txt` 附在 Release 附件中，一行一個檔案：

```text
<64 位小寫十六進位雜湊>  MYAPP-v1.0.0-Setup.exe
<64 位小寫十六進位雜湊>  MYAPP-v1.0.0-Portable.exe
```

- 校驗碼**必須**由**實際上傳的那份檔案**計算，且在上傳後複驗一次。

### 4.4 Release 頁面

- 標題**必須**為：`[<專案名稱>] v<版本號> Release`
- 內文**必須**為 `CHANGELOG.md` 中**該版本區塊的內容**，不含其他版本。
- 附件**必須**包含全部產物與 `SHA256SUMS.txt`。
- 預發佈版本（`-alpha` / `-beta` / `-rc`）**必須**勾選 Pre-release。
- 內文**禁止**貼上未整理的 git log。

### 4.5 舊版本的處置

**已發佈的 tag 與 Release**

- 正常情況下**必須**保留，讓使用者能取得舊版。
- 僅在舊發佈**不符合本規範命名慣例**、或內容有誤而必須撤下時，才刪除並重發；此時**必須**在新版本的 `CHANGELOG.md` 條目說明。

**被整個替換掉的舊實作**

- 依 `DEVELOPER.md` §8 的分支保留規則辦理：舊實作**必須**以分支保留，**禁止**直接刪除；主分支走新實作。
- 舊實作若是驗證新實作正確性的基準，**必須**在該基準比對通過後才解除保留。

## 5. 範例與註解慣例

- 佔位符**必須**用角括號加繁中描述：`<專案名稱>`、`<版本號>`、`<形式>`。
- 虛構專案一律用 `MYAPP`，虛構版本號一律 `v1.0.0`。
- 範例指令**必須**能原樣執行（佔位符除外）。

建立與推送 tag：

```bash
git tag -a v1.0.0 -m "Release v1.0.0"
git push origin v1.0.0
```

產生校驗碼：

```powershell
Get-FileHash .\release\*.exe, .\release\*.zip -Algorithm SHA256 |
  ForEach-Object { "$($_.Hash.ToLower())  $(Split-Path $_.Path -Leaf)" } |
  Out-File .\release\SHA256SUMS.txt -Encoding utf8
```

---

## 6. 禁止事項

- **禁止**在產物檔名使用 `A-Za-z0-9.-_` 以外的字元（含中括號與空格）——GitHub 會把它們換成點，導致本機與線上檔名不一致。
- **禁止**使用 §2.2 以外的形式標記。
- **禁止**在 tag 或產物檔名省略 `v` 前綴。
- **禁止**在同一版本重複發佈不同內容的產物。
- **禁止**未附校驗碼就發佈。
- **禁止**在 `CHANGELOG.md` 尚未更新的情況下建立 Release。
- **禁止**把憑證、金鑰、密碼放進產物或版本控制。
- **禁止**在 Release 內文貼上其他版本的變更內容。
- **禁止**直接刪除被替換掉的舊實作而不留分支。

- [ ] §4.1 發佈門檻六項全部成立
- [ ] 產物形式與 `DEVELOPER.md` §7 所列完全相符，一種都沒少
- [ ] 每個產物檔名符合 `<專案名稱>-v<版本號>-<形式>`，且只用 `A-Za-z0-9.-_`
- [ ] tag 為 `v<版本號>`，建立在實際打包的 commit 上
- [ ] 需要簽章的產物已簽章；自簽時 README 已說明 SmartScreen 警告
- [ ] `SHA256SUMS.txt` 涵蓋所有產物，且已於上傳後複驗
- [ ] Release 標題為 `[<專案名稱>] v<版本號> Release`
- [ ] Release 內文只含本版本的 `CHANGELOG.md` 區塊
- [ ] 預發佈版本已勾選 Pre-release
- [ ] 舊 tag／Release 的處置已決定；若刪除，已在 `CHANGELOG.md` 說明
- [ ] 被替換的舊實作已依 `DEVELOPER.md` §8 建立保留分支
- [ ] 實機下載一次產物並驗證校驗碼與可執行性
